# Codex Project Transfer — Windows 0.2.0

프로젝트 파일과 대화를 다른 PC의 **Codex Windows 앱**으로 옮깁니다. 복원 상위 폴더를 선택하면 그 아래에 **원래 프로젝트 이름**으로 파일을 복원하고, 대상 Codex 앱에 프로젝트와 채팅을 등록합니다. CLI 로그인·재개는 사용하지 않습니다.

예: 원본 `E:\Codex\CodexProjectTransfer`, 복원 상위 폴더 `D:\Work` → `D:\Work\CodexProjectTransfer`. 그 안에 `project`나 별도 `codex` 폴더를 만들지 않습니다.

## 실행 파일

[최신 데스크톱 복원 미리보기 릴리스](https://github.com/cdhun0218/CodexProjectTransfer/releases/tag/v0.2.0)

ZIP 전체를 풀고 `CodexProjectTransfer.exe`를 실행하세요. `_internal` 폴더를 함께 유지해야 하며 Python 설치는 필요하지 않습니다. 대상 PC에는 Codex Windows 앱을 설치하고 한 번 실행해 로그인한 상태여야 합니다.

## 원본 PC에서 백업

1. 관련 Codex 작업과 프로젝트 파일 편집을 멈춥니다.
2. 내보내기 탭에서 프로젝트 폴더와 Codex 저장소(기본 `%USERPROFILE%\.codex`)를 선택합니다.
3. 프로젝트 분석으로 연결된 대화를 확인하고 필요하면 인수인계 메모를 적습니다.
4. 프로젝트 폴더 바깥에 `.codextransfer` 패키지를 저장합니다.
5. 패키지와 이 프로그램을 다른 PC에 복사합니다.

## 대상 PC에서 복원하고 앱에서 이어가기

1. **Codex Windows 앱과 모든 Codex 작업을 완전히 종료**합니다. 실행 중에는 복원이 차단되며 강제 종료하지 않습니다.
2. 복원 탭에서 패키지, **복원 상위 폴더**, 대상 Codex 저장소를 선택합니다.
3. **프로젝트 · 앱 채팅 복원**을 누르고 표시된 최종 경로와 대화 수를 확인합니다.
4. 복원이 끝나면 Codex Windows 앱을 다시 실행합니다.
5. 복원된 프로젝트를 선택하고 기존 채팅을 열어 이어갑니다. 프로그램의 **Codex 앱에서 대화 열기** 버튼도 사용할 수 있습니다.

**v0.1 / v0.1.1에서 만든 패키지도 그대로 사용 가능합니다.** 예전 버전으로 복원한 `project/`, `codex/` 폴더가 있다면 원래 패키지를 이 버전으로 다시 복원하세요. 같은 이름의 프로젝트 폴더가 이미 있으면 덮어쓰지 않으므로 다른 상위 폴더를 선택해야 합니다.

## 기존 데이터와 백업

- 대상 PC의 기존 프로젝트, 채팅, 로그인, 설정은 유지합니다.
- 같은 대화 ID가 이미 있으면 기존 대화를 덮어쓰지 않고 **새 ID의 대화 사본**을 등록합니다.
- 프로젝트 테이블, 프로젝트 경로, 채팅과 프로젝트의 연결, JSONL 대화 원본, 앱의 프로젝트 목록을 함께 갱신합니다.
- 작업 경로 메타데이터는 새 프로젝트 경로로 바꿉니다. 과거 사용자·응답 메시지 본문은 유지합니다.
- `CODEX_HOME`을 바꾸거나 별도 저장소로 앱을 실행하지 않습니다.
- 변경 전 DB와 파일은 대상 저장소의 `transfer-backups/<작업ID>/`에 보존됩니다. 복원 결과 `receipt.json`, 인수인계 메모와 참고 지침도 여기에 저장합니다.
- 처리 중 오류가 발생하면 추가한 정보와 파일을 되돌립니다. 비정상 종료 후에는 앱을 닫은 상태로 **중단된 복원 복구**를 사용하세요. 추출된 프로젝트 파일은 보존합니다. 중단 이후 채팅이나 설정이 바뀌었다면 자동 복구를 멈춥니다.
- 여러 파일의 갱신을 완전한 하나의 파일시스템 트랜잭션으로 만들 수는 없습니다. 비정상 종료가 있었다면 Codex를 먼저 열지 말고 복구 기능을 사용하세요.

## 저장 방식과 기억

| 내용 | 처리 |
|---|---|
| 프로젝트 소스·문서·프로젝트 `AGENTS.md`·`.codex` | 원래 프로젝트 이름의 폴더에 복원 |
| JSONL 대화 원본 | 대상 Codex `sessions`에 추가 |
| 제목·생성일·보관 상태·채팅 인덱스 | 대상 DB에 새 행으로 병합 |
| 프로젝트와 채팅 연결 | 대상 프로젝트 DB와 데스크톱 상태에 등록 |
| 대화 표시 캐시 | 이식한 JSONL에서 재구성하도록 legacy 읽기 모드 사용 |
| 전역 `AGENTS.md`·인수인계 메모 | 백업 폴더 아래 `reference/`에 참고용 보존 |
| 로그인 토큰·전역 설정·플러그인·전역 메모리 DB | 이전하지 않음; 대상 PC의 설정 유지 |

대화 기록을 옮기는 것과 모델의 영구 기억을 복제하는 것은 다릅니다. 이어가는 대화는 저장된 기록과 요약을 이용하며 프로젝트 지침은 파일로 읽힙니다. 참고용 전역 지침과 인수인계 메모는 자동 주입하지 않습니다.

## 호환성과 제한

- 공식적인 백업·복원 API가 아닌 **Codex 내부 저장 형식**을 사용합니다. 대상 PC에 프로젝트 테이블을 포함하는 지원 스키마가 없거나 백업보다 오래된 스키마이면 중단합니다. 양쪽 PC의 Codex 버전을 맞추세요.
- 자동 검증은 독립된 저장소에서 실제 Codex 백엔드의 프로젝트 목록, 프로젝트별 채팅 목록, 사용자·응답 메시지 조회까지 수행했습니다. **다른 PC의 데스크톱 화면에서 실제 메시지를 보내는 최종 동작은 별도 확인이 필요합니다.**
- 일반 Git 체크아웃만 지원하며 `.git` 파일을 쓰는 worktree는 거부합니다. 다른 경로의 worktree·하위 에이전트와 프로젝트 밖 첨부파일은 자동 수집하지 않습니다.
- 대화 본문·도구 인수·설정에 적힌 절대 경로는 일괄 치환하지 않습니다. 대상 PC의 외부 도구와 플러그인은 별도 설정이 필요합니다.
- 기본 제외: `node_modules`, 가상환경, 일부 캐시, 링크/junction, `.env` 계열(예제 제외), 일부 개인 키 파일. 제외 목록은 패키지 `manifest.json`에 기록됩니다.
- 패키지는 암호화되지 않은 ZIP입니다. 일반 코드나 채팅 본문 속 비밀정보까지 자동 탐지하지는 않습니다. 신뢰하는 출처의 패키지만 복원하세요.
- 파일 SHA-256, 압축 경로 탈출, Windows 예약 이름, 중복 경로, 링크, 용량을 검사합니다. SHA-256은 출처 인증이 아닙니다.

## 개발

```powershell
python -m unittest -v test_transfer test_desktop_restore test_desktop_backend
./build.ps1 -Python 'C:\path\to\python.exe'
```

Python 3.12+와 Tkinter를 사용합니다. Windows 공식 CPython으로 빌드하세요. `test_desktop_backend`는 설치된 Codex 백엔드를 별도 임시 저장소에서 사용하며 실제 계정이나 모델 호출을 사용하지 않습니다. `transfer_core.restore_bundle`은 이전 격리 복원 형식의 호환 테스트용으로 남겨두었고 GUI는 `desktop_restore.restore_desktop`을 사용합니다.

주요 파일: `app.py` (한국어 GUI), `transfer_core.py` (패키지·경로 검사), `desktop_restore.py` (앱 저장소 병합·백업·복구).
